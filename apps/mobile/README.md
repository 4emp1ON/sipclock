# Sipclock mobile

Expo SDK 57 app (React Native 0.86, New Architecture, Hermes, Expo Router, React Compiler) for iOS and Android. Part of the pnpm + Turborepo monorepo; the design tokens come from the `@sipclock/tokens` workspace package.

## Run

From the repo root (Node 24):

```bash
pnpm --filter @sipclock/mobile start        # Metro dev server
pnpm --filter @sipclock/mobile typecheck
pnpm --filter @sipclock/mobile test         # Jest (jest-expo)
pnpm --filter @sipclock/mobile lint         # Biome
```

Copy `.env.example` to `.env.local` for `EXPO_PUBLIC_SENTRY_DSN` and `EXPO_PUBLIC_API_URL`.

**Expo Go is not enough.** Native tabs, `@expo/ui` and Sentry need native code that Expo Go does not bundle, so use a development build:

```bash
npx eas-cli@latest build --profile development --platform ios     # or android
```

Then `pnpm --filter @sipclock/mobile start` and open the dev client. Profiles are in `eas.json` (development: dev client, internal; preview: internal; production).

**Local native builds are blocked for now.** SDK 56+ needs Xcode 26.4 or newer to run `expo run:ios`; the local machine has Xcode 26.2. Until Xcode is updated, build in the cloud with EAS. Do not commit `ios/` or `android/`: they are generated (CNG) from `app.json` and config plugins. Bundle IDs (`app.sipclock`) are placeholders.

## Structure

```
src/app/          Expo Router: _layout (fonts, splash, Sentry, SQLite + bar providers, Stack), (tabs)/ native tabs (index = Today, my-bar, favorites, search), recipe/[id]
src/components/   Screen, Text, Chip, Button, AbvBadge, PickCard, Placeholder, app-tabs
src/hooks/        useTheme, useNow, useBar (BarProvider)
src/data/         expo-sqlite: db (migrations, sipclock.db), bar + kv repositories (injected Db, tested with a fake)
src/lib/          time, theme, typography, fonts, locale, strings (en/ru UI copy), recommend-input, availability-label, makeable (+ tests)
src/global.css    Tailwind + Uniwind entry, imports the token stylesheet
metro.config.js   withUniwindConfig wrapper
```

`src/uniwind-types.d.ts` is generated by Metro (className typings); commit it, do not edit it.

## Theming

Styling is [Uniwind](https://docs.uniwind.dev) (Tailwind v4 for React Native). The design has two themes, `night` (primary, dark) and `day` (light). They map onto Uniwind's built-in `dark` and `light` variants, so the theme follows the system color scheme (`userInterfaceStyle: automatic`).

- `packages/tokens` generates `generated/uniwind.css` from `tokens.json`: every color as `--color-<name>` under `@variant dark` (night) and `@variant light` (day), plus radius and the `shadow-card` utility. `global.css` imports it as `@sipclock/tokens/uniwind.css`. After changing tokens run `pnpm tokens`.
- Use utilities such as `bg-bg`, `bg-surface`, `text-ink`, `bg-primary`, `rounded-lg`, `rounded-pill`, `shadow-card`. Never hardcode hex values in app code.
- Fonts cannot be picked with `font-*` utilities in React Native (one loaded family per weight). Use the `Text` component: `variant` selects a token text style (`time-hero`, `drink-title`, `body`, `label`, ...) and resolves Unbounded (display) or Onest (text) at the right weight; `tone` selects the color.
- APIs that cannot take `className` (native tab bar, navigation theme) use `useTheme()`, which returns raw token colors for the current scheme.
- Fonts (`@expo-google-fonts/unbounded`, `@expo-google-fonts/onest`) load through `expo-font` in the root layout; the splash screen stays up until they are ready.

## Sentry

`Sentry.init` runs in `src/app/_layout.tsx` only when `EXPO_PUBLIC_SENTRY_DSN` is set. The `@sentry/react-native/expo` config plugin is intentionally **not** added yet (no org/project); add it, plus source-map upload settings, once the Sentry project exists.
